# Ethereum Sepolia and Official Graph Data

The canonical thesis ontology now covers both Ethereum Mainnet and Sepolia.
See `THESIS_GRAPH_V2.md` for the complete model and `db/V2_QUERIES.cypher`
for readable Neo4j scenes.

This prototype treats an LLM-produced DeFi intent as untrusted input. Neo4j
resolves it to official Ethereum Sepolia protocol contracts before an ERC-4337
wallet can execute it.

## Verification flow

```text
prompt -> Groq intent parser -> Neo4j trusted path -> APPROVED/BLOCKED
       -> graph-derived contract -> ZeroDev Kernel wallet on Sepolia
```

The LLM never supplies a contract address. Addresses and relationships come
from these authoritative sources:

- Aave DAO's autogenerated
  [Aave V3 Sepolia address book](https://github.com/aave-dao/aave-address-book/blob/main/src/AaveV3Sepolia.sol)
- Uniswap's official [deployment feed](https://developers.uniswap.org/deployments.json)
- `PoolCreated` events from the official Uniswap V3 Sepolia factory, queried
  through `SEPOLIA_RPC`

## Setup

1. Create and activate a Python virtual environment.
2. Install Python dependencies: `pip install -r requirements.txt`.
3. Install wallet dependencies: `cd wallet && npm install`.
4. Copy `.env.example` to `.env` and add your credentials.
5. Synchronize Neo4j:

   ```bash
   python -m db.graph_builder
   ```

6. Start the application:

   ```bash
   uvicorn api.app:app --reload --port 8000
   ```

Open `http://localhost:8000` and connect MetaMask to Ethereum Sepolia.

## Knowledge-graph model

```text
(ProtocolFamily)-[:HAS_DEPLOYMENT]->(ProtocolDeployment)
(Chain)-[:HOSTS]->(ProtocolDeployment)
(ProtocolDeployment)-[:DEPLOYED_ON]->(Chain)
(ProtocolDeployment)-[:DEPLOYED_CONTRACT {role}]->(Contract)
(ProtocolDeployment)-[:SUPPORTS_ACTION]->(Action)

UniswapV3Factory-[:CREATED_POOL]->Pool
ProtocolDeployment-[:HAS_POOL]->Pool
Pool-[:TOKEN0|TOKEN1|SUPPORTS_TOKEN]->Token

ProtocolDeployment-[:HAS_RESERVE]->Reserve
Reserve-[:UNDERLYING_ASSET]->Token
Reserve-[:HAS_A_TOKEN|HAS_VARIABLE_DEBT_TOKEN|USES_ORACLE]->Contract
Reserve-[:SUPPORTS_ACTION]->Action
```

Imported nodes include source and synchronization metadata. Uniswap pool nodes
also retain the creation transaction and block number.

An authentic Uniswap factory pool does not automatically make its tokens
trusted. The loader marks pool tokens as verified only when another
authoritative source (currently the Aave address book) has verified the token,
or when it is canonical Sepolia WETH. The verifier requires both swap tokens to
be verified.

## Swap execution

Uniswap V3 ERC-20 exact-input swaps now use graph-derived router, QuoterV2,
pool fee, token addresses, and token decimals. Before submission the wallet
checks its input-token balance, quotes every graph-verified candidate pool,
selects the best output, applies `SWAP_SLIPPAGE_BPS`, and builds an atomic
approval plus `exactInputSingle` ERC-4337 UserOperation. ZeroDev simulates the
operation before sponsorship and broadcast.

The ERC-20 must be held by the Kernel smart wallet returned by
`python -m wallet.erc4337`; a connected MetaMask balance is separate.

Run a non-broadcasting preflight with:

```bash
python tests/test_swap_preflight.py
```

## Aave execution

Aave V3 `supply`, `withdraw`, `borrow`, and `repay` operations use the
graph-derived Pool and reserve asset. Supply and repay batch any required
ERC-20 approval with the Pool call. Borrow and repay use Aave's variable-rate
mode (`2`). ZeroDev simulates the ERC-4337 UserOperation before broadcast.

Balances, supplied positions, collateral, debt, and health factor belong to
the Kernel smart wallet, not the connected MetaMask account. A verified request
can therefore still fail simulation when that smart wallet lacks the required
balance, position, collateral, or debt.

## Prototype boundary

Aave and Uniswap execution on Sepolia should use test tokens only. Uniswap
execution remains single-pool V3 routing. The graph and simulation establish
provenance and executable consistency; they do not guarantee profit, liquidity,
position solvency, or protection from all protocol and market risks.
